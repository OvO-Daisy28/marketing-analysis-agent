# 企业接入、成本与推广分析

[项目首页](../README.md) · [方案与产品对标](solution-analysis.md) · [POC 验证](validation.md) · [运行指南](operations.md)

> **交付判断：**当前版本适合公开演示和本地复现。企业试点应从一个团队、一个获授权的数据集和固定转化口径开始；完成数据隔离、缺数据确认、累计预算及运维补齐后，才能开放受控试用。尚未完成真实客户接入或生产验收。

分析日期：2026-11-24。实现依据为 `50751a7` 及本轮发布接口回归测试；价格示例为预算假设，不是供应商报价。本文承接需求、产品对标、优化设计和 POC 验证，回答“谁适合接入、如何交付、花费多少、何时继续或停止”。

## 1. 谁适合接入，哪些需求应先排除

| 客户条件 | 建议 | 原因 |
|---|---|---|
| 已有可靠指标数据，运营经常做流量分组复盘，需要可修改报告 | 优先访谈并开展受控试点 | 与报表 Skill 和研究 Loop 主线接近，数据计算可以复用 |
| 已部署神策、帆软、Quick BI 等分析平台，但报告整理和证据复核仍费时 | 先检查现有平台是否已能解决；有明确缺口再集成 | 通过授权查询接口复用指标口径，避免再造数据平台 |
| 数据字段混乱、没有购买定义或负责人 | 先治理数据，再做 Agent | Agent 无法代替指标定义与数据核对 |
| 需要广告预算执行、因果归因、实时推荐或跨用户留存 | 超出当前交付范围，另做需求和数据评审 | 当前系统支持描述性分析与报告，不具备对应数据和执行接口 |
| 要求立即承诺大规模并发、高可用或私有化模型推理 | 单独开展容量、部署与资源评估 | 现有小规模恢复测试不能推导生产 SLA；自部署模型需另计资源 |

本项目的推广对象是有重复分析任务的运营团队与其数据负责人。先确认“为什么现有 BI 加人工还不够”，再判断定制是否值得。若现有产品配置即可覆盖需求，优先配置或集成；产品能力比较见[对标报告](solution-analysis.md#benchmark)。

## 2. 企业接入清单

以下是接入前需要双方确认的清单，均不表示已与企业完成对接。

| 检查项 | 企业应提供 | 实施方工作与验收材料 | 当前状态 |
|---|---|---|---|
| 场景与成功标准 | 一个典型报告、一组研究问题、业务审阅人、现行人工流程 | 固定需求与通过/失败条件；约定不支持的任务 | 有公开案例，客户需求待确认 |
| 数据与授权 | 获准样本、只读接口或视图、字段字典、数据负责人 | 映射到受控 Query；核对粒度、重复、缺失、刷新和版本 | 仅有 UCI 导入，企业连接器待建 |
| 指标口径 | 分子分母、会话/用户/订单粒度、购买定义、时间与时区 | 指标注册及独立 SQL/CSV 对账；确定舍入容差 | 三项会话指标已实现；其他指标需单独定义 |
| 身份与权限 | 用户名单、组织边界、可查数据及导出范围 | SSO/账号接入；查询前行列过滤，证据与导出继承权限 | 当前个人工作区隔离；共用 UCI 数据，没有企业数据权限 |
| 模型服务 | 获准供应商、API 额度、限流及使用条款 | 验证 function calling、超时、usage；确认哪些查询结果可发模型 | 已有兼容适配；企业供应商和数据外发边界待确认 |
| 网络与运行环境 | 主机、网络入口、域名、数据源连通条件 | 同源 HTTPS、SSE 代理、Origin、数据库持久化、健康检查 | Compose 可复现；远程试用配置未交付 |
| 数据留存 | 会话/证据/导出保留期、删除与审计要求 | 删除流程、日志字段、备份与恢复演练 | 持久化已有，生命周期治理待建 |
| 容量与预算 | 同时分析人数、峰值任务量、可接受排队和月预算 | 测排队/运行 P95、失败率、资源占用及 Token；设置总额度 | 单 Run 限制已有，工作区和 Goal 累计额度待建 |
| 交付与运维 | 业务验收人、系统负责人、故障联系路径 | 交付版本、操作手册、回退与升级说明，完成签收 | 开源文档已有，客户交接未发生 |

先用客户获准的样本进行离线核算，再接只读数据源。明确区分源系统事件时间和导入时间；不能将订单行直接当作会话行。创建任务时绑定客户数据集和口径版本，当前 `latest_dataset` 的全局选择方式需调整后才能服务不同企业数据。

## 3. 建议的接入与部署方案

**数据接入：**复用企业已有 BI/数据服务的只读聚合接口，或建设受控数据库视图适配层。Agent 仍调用 `query_metrics`，由后端将允许的维度、筛选和指标翻译成查询；服务端施加用户数据范围。首期不开放任意 SQL，也不要求企业迁移全部数据。

**模型边界：**Worker 会把目标、证据摘要及读取到的结果送给模型。即使只送聚合数据，也需要企业确认字段、颗粒度和供应商处理边界；不允许外发时另评估获准的内网模型服务及其工具调用表现。远端 API 路径不需要本机 GPU。

**试用部署：**建议单主机、单 API、单 Worker 和 PostgreSQL 起步，HTTPS 反向代理统一入口；这只是简化运维的起点，不是容量结论。构建产物在部署前生成，数据库端口不对公网开放。现有 `compose.yaml` 向各服务加载同一 `.env`，需要拆分凭据，并让应用支持文件式密钥读取；仅声明 secrets 不会自动改变代码读取行为。[Docker Compose secrets 官方说明](https://docs.docker.com/compose/how-tos/use-secrets/)

受控试用前补齐：获准账号入口、readiness 和 Worker 心跳、外部备份及恢复、单 Goal/工作区累计预算、替代任务确认、企业数据归属与权限。现有研究完成和用户发布保持分离；发布时冻结完整结论与证据内容仍属于目标设计。当前与目标部署图见[架构文档](architecture.md)和[优化部署方案](solution-analysis.md#target-design)。

## 4. 成本估算：可替换参数的预算模型

### 4.1 计费口径

月成本 = 模型调用 + 主机/数据库 + 存储/备份 + 网络/监控 + 运维人工。一次性交付费用另外计算：需求、数据映射、权限接入、开发、验收与培训。已有资源也记录占用和人员投入，不能直接视为零成本。

模型费用按供应商实际规则拆分：

```text
模型费用 = Σ[输入 Token × 输入单价 + 输出 Token × 输出单价] / 1,000,000
         + 单独收费的服务项目
```

有缓存、不同模型或时段费率时分别核算。重试、失败、续接和评测调用均计入；usage 缺失部分标为估算，最后与供应商账单对账。官方 API 文档提供分输入/输出的 Token 计费口径，但当前兼容网关的结算价尚未确认，不能套用官方直连价格。[DeepSeek 定价与计费说明](https://api-docs.deepseek.com/quick_start/pricing/)

### 4.2 调用量示例

**下表完全采用假设单价：输入 2 元/百万 Token，输出 8 元/百万 Token。不是当前网关报价。**输入量按历史试跑取整建立预算示例，不是平均值或 P95。完整任务的 Token 包含多轮请求，而非只算用户的一句话。

| 任务 | 假设每次输入/输出 Token | 估算调用费 |
|---|---:|---:|
| 直接报表 | 16,000 / 1,500 | 0.044 元 |
| 多轮研究 | 26,000 / 2,700 | 0.0736 元 |
| 月度组合：2,000 次 Run，70% 报表、30% 研究 | 1,400 次报表 + 600 次研究 | 105.76 元 |
| 增加 25% 调用余量 | 用于超出上述常规 Run 的失败、重试或续接；若已计入实际用量则不重复加 | 132.20 元/月 |

历史依据是两次 smoke 的用量（直接报表 15,147/1,283，研究 25,280/2,652）和[单次交付记录](results/live-delivery-check.json)，只能说明这个量级曾出现。正式历史集为 86 次、共 2,135,588 Token，含失败请求保守预留，见[评测汇总](results/evaluation-summary.json)。不把这组历史实验推成企业月均账单。

敏感性：相同组合下，500/2,000/10,000 次 Run 对应约 33.05/132.20/661.00 元（含假设余量）。若单次 Token 或供应商单价翻倍，调用部分近似翻倍；并不意味着总体运营成本同比例变化。

### 4.3 月度与一次性实施预算示例

下面各项仍是**可替换的规划参数**，没有采购报价或资源实测。以单主机试点为例，4 vCPU / 8 GiB 可作为询价和压测候选，不能据此承诺支持多少人。选择地区、实例、磁盘、带宽及备份后再获取真实报价。[阿里云价格计算器](https://www.aliyun.com/price/product#/ecs/detail)

| 月度项 | 假设输入 | 估算 |
|---|---|---:|
| API/Worker/PostgreSQL 共用主机 | 自管数据库不再重复算托管数据库费 | 300 元 |
| 独立备份存储 | 容量与保留期后续按证据增长率调整 | 100 元 |
| 网络与监控等 | 若套餐已包含则扣除重复项目 | 100 元 |
| 模型 | 上述 2,000 次 Run 示例 | 132.20 元 |
| 运维人工 | 8 小时 × 150 元/小时 | 1,200 元 |
| **月度总计** | 含人工；不含首次实施、税费及另购服务 | **1,832.20 元** |

托管数据库、SSO、审计平台、生产高可用、私有模型推理需另列；不能在此示例上直接承诺固定总价。

| 一次性工作包 | 规划工作量（人日） | 输出 |
|---|---:|---|
| 需求和样本对账 | 2–3 | 需求范围、数据字典、标准答案 |
| 数据/权限适配 | 4–7 | 只读查询与数据隔离 |
| 任务确认和交付一致性 | 3–5 | 澄清、证据范围、完整发布快照 |
| 部署、预算和恢复 | 3–5 | 受控环境与恢复记录 |
| 回归和业务审阅 | 3–5 | 固定验收集、缺陷及复验记录 |
| 手册和交接 | 2–3 | 演示、培训与运维材料 |
| **合计** | **17–28** | 假设 1,200 元/人日为 **20,400–33,600 元** |

这是针对单团队单数据源的工作量估算，不是工期或商业报价；不含数据治理返工、企业审批等待及大规模架构改造。项目的主要实施成本可能来自数据、权限与验收，而不是 Token。

### 4.4 价值核算

试点记录同一任务使用原流程和 Agent 后的操作时间、等待时间、复核时间、修改次数和结果质量。将人工节省定义为“原人工投入 − 新操作与审核投入”，不把模型等待全部算成人工节省。

例如按上面的月成本 1,832.20 元、人工小时成本假设 100 元，仅抵消月运营成本就需要每月净节省约 18.33 小时；若将首次实施按 12 个月分摊，还需另加入 1,700–2,800 元/月。这只是盈亏平衡计算，项目尚无实测提效或投资回报结论。

## 5. 风险、阻断条件与处理责任

| 风险与已有证据 | 接入前处理 | 责任建议／继续条件 |
|---|---|---|
| 有引用但结论不受支持；历史案例有比较范围错误和臆造年份 | 对每条结论核对范围、样本、证据；人工确认发布 | 业务审阅人＋开发；严重误导结论必须修正后复验 |
| 缺 ROI 数据时模型擅自交付替代任务 | 实现结构化澄清与用户确认，覆盖拒绝、过期和重试 | 开发＋业务；A04 通过前不交付“自动处理任意营销问题” |
| 改范围沿用旧结论 | 已增加 stale 发布拦截；继续补证据 scope 与完整快照 | 开发；本轮修复不等于全部发布治理完成 |
| 企业数据串用或越权导出 | 数据集绑定工作区、行列权限、证据/导出鉴权 | 数据负责人＋开发；发现泄露立即停用相应入口并排查 |
| 续接绕过单 Run 预算 | 增加 Goal/工作区累计额度和并发配额；供应商侧总额度兜底 | 运维＋开发；现有 80,000 Token 上限不是月账单上限 |
| 模型限流、工具错误、队列堆积 | 观测等待与运行时间、有限重试、错误分级；压测后设并发 | 运维；不能把 6 个领取者恢复试验当作生产吞吐量 |
| 主机故障或升级导致数据不可恢复 | 异机备份、恢复演练、镜像与迁移回退计划 | 运维；RPO/RTO 由业务确定并实测，不能默认满足 |
| 用户仍需大量修改，不愿持续使用 | 记录返工原因和人工净耗时，优先优化核心模板 | 方案负责人；若已有 BI 更省成本则停止定制或缩小范围 |

## 6. 实施门槛与推广方式

| 阶段 | 交付内容 | 进入下一阶段的条件 |
|---|---|---|
| 公开展示 | GitHub 文档、固定案例、代码、验证与缺陷记录 | 明示样例/真实模型区别，体验入口可打开；当前可交付 |
| 需求与样本验证 | 一个团队的报告样例、获准数据、明确指标、验收合同 | 企业数据负责人和业务审阅人确认范围；当前尚未开展 |
| 受控试点 | 接入适配、隔离、澄清、预算、备份及试点演示 | 对客户样本执行 A01–A08；数字、越权、重复发布、失效结论和擅自改题等阻断项关闭；语义人工复核 |
| 扩大使用 | 容量报告、运维责任、业务价值记录、服务目标 | 质量与人工投入达到双方预设标准；根据实测成本决定扩展 |

演示建议采用三个连续案例：①生成转化报告并核对分子分母；②提出研究问题、打开引用证据并修改月份；③提出 ROI 请求或注入失败，展示能力边界与停止/恢复。第三例必须按真实结果展示，当前缺数据确认仍有缺口，不能用预置 mock 表现代替真实模型证明。

面向企业介绍时突出“复用已有指标服务，将分析过程和最终报告连起来”。试点推广先通过业务负责人、数据负责人和运维共同评审，再由获准用户试用；本文不代表已经联系客户或获得合作。公开仓库继续使用公开数据，企业配置、凭据和试点数据不随作品集分发。
