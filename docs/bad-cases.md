# 已观察到的失败与取舍

## 工具参数带多余前缀

真实兼容服务返回 `{}{"group_by":...}`，严格 JSON 解析正确地拒绝执行。增加显式兼容开关，仅接受“一个空对象前缀 + 一个完整对象”的特例，并保留原参数与调整记录。回归测试仍拒绝两个非空对象或更多拼接片段。

## 直接报表扩展为过度研究

早期试跑为简单 11 月报表执行了多项无关查询，最后因完成标准字符串不匹配而耗尽预算。改为按任务模式暴露工具、给出明确交付要求，并将 finish 的标准参数约束为当前 Goal 的枚举项。保留预算上限，没有用无限重试掩盖问题。

## 模型结论的比较范围不严谨

正式案例 report-02-full-1 的结论称流量类型 8 最高、类型 13 最低，但全样本中更高/更低的分组仍存在；只有排除小样本后才可能作该比较。模型没有清楚限定比较集合。数值本身正确不能证明该自然语言结论完全正确。

## 模型补入数据未提供的年份

report-18-full-1 中出现了数据未提供的年份。数据只有月份分类，不能从当前时间推断样本年份。该问题记录为语义质量缺陷，不能计入“回答准确率 100%”。页面明确要求发布前核对模型分析与证据。

## 完成任务但遗漏联合分组

部分研究运行取得单维数据并交付报告，却没有执行任务要求的双维联合查询。结构完成门禁只保证存在证据、检查过假设和报告，不保证完全满足自然语言意图。独立 intent_match 检查保留这类失败。

## 数据不支持时自行提供替代报告

部分 ROI、收入金额或因果请求没有进入预期的 waiting_input，而是完成了有限的替代分析，或用尽预算。即便结论写了限制，也不满足当前严格的“先询问”评测标准。首轮按失败记录，不事后放宽评分规则。

## 网络与成本

正式评测包含供应商网络失败和 TOKEN_BUDGET 停止。失败请求用量未知时保留预留值，成本统计偏保守。结果证明停止和留痕机制生效，但不代表网络失败已经被消除。

## 报表版本边界

检查发现从旧版本发起样式修改可能错误沿用最新版本的数据范围。已增加 base_version_id 和幂等请求内容记录：修改继承用户所选版本；同一幂等键用于不同内容会被拒绝。该改动由独立回归测试验证。

## 续接错误复用旧交付物

完整性复查发现 finish 原先只检查 Goal 下存在报告，续接 Run 可以沿用旧报告并提前完成。现在检查当前 Run 的成功 draft_report 工具记录；旧证据可以复用，但本次要求必须交付新草稿。回归测试用一个只会调用 finish 的 Provider 重现并验证拒绝，再验证正常 mock 续接可以完成。此门禁仍不验证自然语言要求是否全部满足。

## 创建目标的幂等比较遗漏完成标准

原先相同 request_key 只比较目标文字与模式，忽略 criteria。现在同时比较生效的完成标准，同一键不能悄悄代表另一组验收要求；重复提交完全相同内容仍返回原 Goal / Run。
